**实测（2026-11-14 22:0x）**：

```
POST /recall {"q":"上周三我们聊了什么","k":5}
→ items=5  time_filter={"start":1793721600.0,"end":1793808000.0}

POST /recall {"q":"你还记得我吗","k":5}
→ items=5  time_filter={"start":null,"end":null}
```

**踩的坑（值得记）**：PowerShell 5 的 `Invoke-WebRequest -Body $jsonString` **默认按 GBK 编码发中文** → 服务端收到乱码 → 解析不出时间词，`time_filter` 一直是 `null`。正确写法是 `$bytes = [Text.Encoding]::UTF8.GetBytes($json)` 再 `-Body $bytes -ContentType "application/json; charset=utf-8"`。**不是代码 bug，是验证方法错了**（我一度去查 pyc 缓存和重复定义，白查两轮）。

## 五、后台运行机制

### 5.1 调度器（本次新增）

`dafeiyu-core/src/dafeiyu/kernel/scheduler.py`

```python
SCHED = Scheduler(ROOT)                          # 状态在 scheduler_state.json
SCHED.allow(name, min_gap=0, max_per_day=0)      # 只查不改
SCHED.done(name, ok=True, note="…")              # 记结果，失败退避
SCHED.pause() / SCHED.resume() / SCHED.stats()
```

- **去重**：`min_gap` 秒内不重复
- **预算**：`max_per_day` 跨天（`time.strftime("%Y-%m-%d")`）自动重置
- **退避**：连续失败 `backoff_until = now + min(3600, 60 * 2^(fails-1))`
- **持久化**：`.tmp` → `os.replace` 原子写，重启后 `_load()` 读回
- **不崩**：坏文件返回空状态，不抛
