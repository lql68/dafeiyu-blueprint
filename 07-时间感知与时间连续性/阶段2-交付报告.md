## 八、尚未解决的问题

### 8.1 「上次互动」重启即失忆

`_LAST_TALK` 是进程内变量。**8770 重启后为 0** → 她不会说「你上次说话是 3 小时前」。

这是**阶段 2 明确不做持久化的结果**（指令第六节「不实现 last_active_at 的新持久化机制」）。真正要解决得等阶段 5 的离线连续性。

**当前行为是安全的**：不知道就不提，不编造。

### 8.2 「上次互动」只看网页/QQ 说话，不含主动开口

`heard` 为空（`_proactive_loop` 主动开口）时不更新 `_LAST_TALK`。这是有意的 —— 主动开口不是「他说话」。但如果她主动开口后你马上回她，间隔会按「你上一次说话」算，可能偏大。

### 8.3 时钟回拨只能检测，不能纠正

`temporal.elapsed()` 遇到未来时间戳返回 `0.0`（`offline()` 里 `clock_went_back: true`）。**检测到了，但没有「以哪个为准」的策略** —— 因为阶段 2 没有持久化的「已知正确时间」可以比对。

### 8.4 日期没进 `context()` 的正文

`context()` 现在给的是「现在是周四 深夜 22:22」—— **有星期，没有「几月几号」**。

`now()` 返回的 `datetime` 里有日期，但 `context()` 拼的句子没带。如果她需要说「今天是 11 月 12 号」，现在拿不到。

**没有擅自加**：指令说「保持上下文简洁，不要让时间信息挤占主要对话内容」，且当前需求是「几点/什么时段」，日期属于阶段 3（时间化记忆）的范畴。

## 补 3 · 并发安全

### 竞争是真的，但很小

`ThreadingHTTPServer` 每个请求一个线程，两路会同时碰 `_LAST_TALK`：

- `POST /api/talk` → `think()` 读旧值 + 写新值
- `GET /temporal` → 只读

**原写法**：
```python
_prev_talk = _LAST_TALK[0]
if heard:
    _LAST_TALK[0] = time.time()
```
读和写之间有空隙 —— 两个人同时说话时，第二个会读到第一个**刚写进去的值**，间隔算成 0，本来该是「几秒前」。

### 改动（`voice_server.py:129-150`）

```python
_LAST_TALK = [0.0]
_LAST_TALK_LOCK = threading.Lock()


def _take_prev_talk():
    """原子地「读旧值 + 写当前时刻」，返回旧值。"""
    ts = time.time()
    with _LAST_TALK_LOCK:
        prev = _LAST_TALK[0]
        _LAST_TALK[0] = ts
    return prev


def _peek_last_talk():
    """只读快照，给 `/temporal` 这类观察者用。"""
    with _LAST_TALK_LOCK:
        return _LAST_TALK[0]
```

`think()` 里：
```python
if heard:
    _prev_talk = _take_prev_talk()   # 读+写原子
else:
    _prev_talk = _peek_last_talk()   # 只读
```

`/temporal` 里：`lt = _peek_last_talk()`。

**语义没变**：仍然只在 `heard` 非空时更新（主动开口不算「他说话」）。

### 并发测试的判据（这里踩了个坑）

第一版断言「50 个线程拿到的旧值必须两两不同」—— **失败了，但不是锁的问题**：

```
assert 49 == 9
[1794494091.1292644, 1794494091.1292644, 1794494091.1302693, ...]
```

**Windows 上 `time.time()` 的分辨率约 15.6 ms**，50 个线程在同一时间片里跑完，写进去的值本来就一样。拿「各不相同」当判据是错的。

**改成真正的判据**：**初始值 0 只能被一个线程看到**。没有锁时多个线程会同时读到 0。

```python
zeros = [v for v in got if v <= 0]
assert len(zeros) <= 1, "初始值 0 被 %d 个线程看到了 —— 读-写不是原子的"
```

连跑 5 次，**5/5 通过**。

## 补 4 · 鉴权检查

### 现有约定：**只绑回环，应用层不做鉴权**

`voice_server.py:1761`：
```python
srv = ThreadingHTTPServer(("127.0.0.1", a.port), Handler)
```

全文件搜 `Authorization` / `token` / `client_address` / IP 白名单 —— **零命中**（`vts/status` 里的 `authed` 是 VTS 自己的，不是 8770 的）。

**这就是现有约定**：8770 是纯本机服务，安全边界是「只监听 127.0.0.1」。

### `/temporal` 的遵守情况

**遵守**：

1. 挂在同一个 `Handler` 上 → 同样只绑 127.0.0.1，外部网络到不了。
2. **不加额外鉴权** —— 加了才是不一致（别的 `/api/*` 都没有）。
3. **只读**：不写数据库、不写 JSON、不改 `_LAST_TALK`（用 `_peek_last_talk()`）。
4. **不泄露敏感信息**：返回里只有时间、时区、星期、昼夜、上下文、上次互动时刻。**没有** MCP key（在 `world.json`）、**没有** OneBot token、**没有** 密码。
5. **错误有状态码**：`TEMPORAL` 不可用 → `503`；时区配置错 → `500`；其他异常 → `500`。

测试里有专门一条扫这个：

```python
def test_不泄露敏感字段(self):
    blob = json.dumps(j, ensure_ascii=False).lower()
    for bad in ("token", "password", "secret", "apikey", "mcp"):
        assert bad not in blob
```

### 从别的机器能不能访问？

不能。`127.0.0.1` 只在本机回环。**如果以后要局域网访问**，得改成 `0.0.0.0` 并同时加鉴权 —— 那是另一件事，这次没动。
