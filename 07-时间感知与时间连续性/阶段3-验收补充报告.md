## 三、端到端验证：真 `search_memories` 代码路径

### 方法

不用 mock 复制品，而是用 `MemoryEngine.__new__` 绕过 `initialize()`（那里会建一批后台任务，实测 5 分钟不返回），只手塞 `search_memories` 需要的属性，然后直接调**真 `MemoryEngine.search_memories`**。

构造三条检索结果：

| doc_id | 内容 | `atom_event_time` | `time_precision` |
|---|---|---|---|
| 1 | 昨天去河边钓鱼 | 昨天 14:00 | exact |
| 2 | 今天在家看书 | 今天 15:00 | exact |
| 3 | 我喜欢吃苹果 | `None` | unknown |

### 结果

```
① 不带时间（旧行为）        : 3 条 -> [1, 2, 3]
② 只查「昨天」              : 2 条 -> [1, 3]
③ 只查「今天」              : 2 条 -> [2, 3]
④ 查 20~30 天前（无命中但应该有 unknown）: 1 条 -> [3]

========================================================
① 无时间参数保持旧行为      : PASS
② 昨天只命中昨天那条        : PASS
③ 今天只命中今天那条        : PASS
④ 无命中期时 unknown 仍保留 : PASS
========================================================
```

**四项全 PASS**，且都在**真 `search_memories` 函数体**内完成（不是复制逻辑）。

具体证明：

- **① 旧行为不变**：不传 `start_ts/end_ts` 时走原路径，3 条原样返回
- **②③ 时间过滤生效**：明确时间且不在查询区间的被 `excluded` 掉（钓鱼 1 在「今天」查询里被排除，看书 2 在「昨天」查询里被排除）
- **④ `unknown` 不被静默删除**：`doc_id=3`（无事件时间）在任何时间查询里都保留，而且**排在 matched 之后**

## 四、本轮新发现并修复的一个真 bug

### `atom_time` 的收集位置错了

**原实现**（阶段 3 第一次提交）：

```python
for atom in atom_results:
    if atom.parent_memory_id not in existing_ids:        # ← 只在补充分支里
        scores[...] = ...
        _ev = getattr(atom, "event_time", None)
        if _ev and _prec and _prec != "unknown":
            atom_time[atom.parent_memory_id] = {...}     # ← 只有补充的才收
```

**后果**：**hybrid 检索已经命中的文档，其 atom 即使有明确事件时间，也拿不到 `atom_event_time`** → 过滤时进 `unknown` → **时间过滤对主命中的文档永远无效**。

这直接违反用户要求的「文档层和 Atom 层都必须纳入时间过滤，不允许只过滤 atoms 而遗漏文档」。

**修复**：把 `atom_time` 的收集**移出补充分支**（对**所有** `atom_results` 收集），循环结束后统一补到已有 `results` 上：

```python
atom_time: dict[int, dict[str, Any]] = {}
for atom in atom_results:
    _ev = getattr(atom, "event_time", None)
    _prec = getattr(atom, "time_precision", "unknown")
    if _ev and _prec and _prec != "unknown":
        if atom.parent_memory_id not in atom_time:
            atom_time[atom.parent_memory_id] = {
                "atom_event_time": _ev,
                "atom_event_time_end": getattr(atom, "event_time_end", None),
                "atom_time_precision": _prec,
                "atom_temporal_status": getattr(atom, "temporal_status", "unknown"),
            }
    if atom.parent_memory_id not in existing_ids:
        scores[atom.parent_memory_id] = max(
            scores.get(atom.parent_memory_id, 0), atom.final_score
        )
# 把收集到的事件时间补回「已经在 results 里」的文档
if atom_time:
    for _r in results:
        _t = atom_time.get(_r.doc_id)
        if _t:
            _md = dict(_r.metadata or {})
            _md.update(_t)
            _r.metadata = _md
```

**这个 bug 就是端到端验证跑出来的**——如果只跑单元测试（`filter_by_event_time` 单测），永远发现不了。
