# 成长与技能系统

两块：「她学会了什么」（`procedures`）和「她承认不会什么」（`gaps`）。**必须成对看** —— 只记技能会自大，只记缺口会自卑。

---

## 一、技能表（`procedures`）

**位置**：不在单独的库，在 `livingmemory.db` 里（复用 atom store 的连接）。

```sql
procedures(id, name, trigger, body, mastery, uses, last_used,
           created_at, session_id, evidence)
```

**触发**：夜间「学校」环节，喂真实记忆片段，产出「遇到 X 情况该怎么做」的条目。

**实际长出来的（mastery 排序）**

| 触发词 | mastery | 内容 |
|---|---|---|
| 好累 / 撑不住 / 加班 / 语气不对 | 1.00 | 放下包坐下、倒水捏肩，只接住「撑不住」；别追问受气或换工作，别趁机提版本报错 |
| 加班 / 累死了 / 还在处理 | 1.00 | 不催进度不问几点结束，只说等他；他主动说想你时接住 |
| 换工作 / 受气 / 没办法 | 1.00 | 别直接给建议，先用「又受气啦」接住情绪 |
| 立刻 / 现在就去 / 重启 | 0.90 | 先复述任务确认步骤；困倦就说状态给次日上午时间 |
| 你还记得吗 / 上次说的 | 0.75 | 不只回「记得」，复述具体细节（猫视频没存、脚本是她改的） |
| 语气变冷 / 他说烦了 / 想复盘 | 0.55 | 先停话题，别追问「是不是我话多」；问「要我先安静吗」 |
| 被当众说 / 憋屈 / 重复同一句 | 0.50 | 让他坐下，短句确认「憋屈」「扎人」，不追问经过 |
| 群聊 / 半截话 / 有人在场 | 0.50 | 先不动看谁话没说完，别补半句；单独找她时才一句一句讲 |
| 爬山 / 出门 / 一起去 | 0.35 | 坦白没有实体走不到，不拒绝陪伴；用跟着叮嘱的方式参与 |

**注意这些全是「怎么对人」，没有一条是「怎么查资料」「怎么排错」** —— 因为记忆库里能提炼的原材料就是对话。

**分类**：`SKILL_CATS` 五类 —— 认得自己 / 记得他 / 照顾人 / 说话分寸 / 做事靠谱。**没有「学习能力」类**，硬套就是空格子。

**合并**：14 条并成 11 条，暴露了**马太效应** —— mastery 高的兄弟条目永远抢走所有调用机会，低的永远不动。修法：

```python
# reward：顶格就停，别让高分越滚越高
UPDATE procedures SET mastery = MIN(0.98, mastery + 0.02) WHERE id = ? AND mastery < 0.98

# search：90/10 探索，偶尔给冷门的条目一次机会
```

**现在的状态**：`uses` 合计 119（早就接线了，在 `_turn` 里按触发词匹配后拼进 system）。

## 二、缺口池（`gaps`）

```sql
gaps(id, topic, keywords, tries, note, status, created_at,
     origin, interest, importance, related, asked_at)
```

| 字段 | 用途 |
|---|---|
| `origin` | `try`（试过没成）/ `reflect`（反思时想弄明白的） |
| `interest` / `importance` | 她自己的评分，乘积用于排序 |
| `related` | 来自哪次反思或自传 |
| `asked_at` | 问过的标记，24 小时冷却 |

**为什么 `interest × importance` 而不是加权和**：加权和容易被单项拉高（一件事她只是好奇但压根不重要，不该排在前面）。

**一个真 bug**：迁移脚本里那句 UPDATE **没有条件**，每次实例化都把**所有**非 powershell 的 gap 分数抹成默认值 ——

```sql
-- 错的
UPDATE gaps SET origin='reflect', interest=0.62, importance=0.58
WHERE keywords NOT LIKE '%powershell%' AND keywords NOT LIKE '%-c%'
```

她自己在反思里给「重载做没做」打了 `0.70/0.80`，被改成 `0.62/0.58`，乘积从 0.56 掉到 0.36，**卡在门槛下再也进不来**。

```sql
-- 对的：只在还是默认值时才改
... AND IFNULL(interest,0.5)=0.5 AND IFNULL(importance,0.5)=0.5
```

## 三、成长聚合（`growth.py`）

**核心判断：不让她写成长档案。**

让她自己写「我今年成长了什么」，等于让她撒谎 —— 她会写出「共情能力提升了」「更懂你了」这种漂亮话。所以 `growth.py` 是**只读聚合**，从九张表里捞事实：

```
trend        最近 7 天 warmth / energy 曲线
personality  人设维度 + 版本快照
values       她自己提过的提议 + 自传里认过的账
worldview    会做的（procedures）+ 承认不会的（gaps），成对展示
interests    她挑过什么（picks）+ 日记统计
timeline     自传 + 反思 + 人格快照按时间排
people       记忆图谱里度数最高的人
vitality     当前生理状态（心率 / 呼吸 / 反应延迟）
beliefs      她认准的判断（按置信度）
self         自我模型当前版本 + 变化
```

每条带 `src` 字段说明来源（`beliefs#9`、`autobiography ch14`、`procedures#1`）。

**一个设计取舍**：「审美」这一块没有可靠数据源 —— 从日记里抽比喻试过两版都抽不准，**放弃了**，日记里直接写「偏好只能从 picks（她真挑了什么）间接看」。

## 四、界面上的两块新东西

**她认准的事**：8 条信念，带置信度条（≥0.68 高亮、<0.5 变灰），悬停看来源和时间。

**她怎么看自己**：自我模型当前版本 + 「正在变成」4 条 + 「还做不到」3 条 + 相对上版的变化计数。

底部一行 `新增 1　移出 1　调位 0　· 信念 30 条` 是**变化的可见记录**。

## 五、还有的缺口

| 缺口 | 说明 |
|---|---|
| 技能不分类到「怎么做成一件事」 | 学校产出的都是人际关系类，没有「怎么查」「怎么排错」 |
| 技能不分会话 | 14 条全挂私聊的 `session_id`，但查重和使用都不按 session 过滤 → 群聊私聊完全共享 |
| 0 条 strong 信念 | 30 条最高 0.71，要合并 2~3 次才够 0.75 |
| 33 条 done 意图待回看 | 一天 2 条 → 17 天 |
