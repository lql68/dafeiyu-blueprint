# 大肥鱼 · 情绪内核落地方案

> 基于 `大鱼鱼_内在情绪生命系统_后端设计指南_v1.0.md`（935 行 / 19 章）+ 你提的「三层保护」与「情绪理解与反思」
>
> 这份不是对原设计的复述，是对照**我们真实已有的代码**做减法：哪部分已经有了、哪部分真缺、怎么接。

---

## 一、先说结论

原设计有 5 个阶段、6 张表、PAD 三维、26 种情绪标签。**对照我们的系统，其中 40% 已经跑起来了，25% 是重复建设，真正缺的只有三件事。**

| 原设计的模块 | 我们的现状 | 判断 |
|---|---|---|
| 生理底层（arousal / 时间尺度） | `rhythm.py` 已跑：`circadian` `arousal` `lag` `hr` `rr` `sleep_stage` | **已有，直接复用** |
| 心境（Mood） | `warmth` 已跑：软顶 + 14%/h 回归 + 感受器适应 + 情绪尖峰 | **已有，是 Mood 的一半** |
| 人格倾向（Temperament） | `persona_versions` 3 次快照 + `dimensions` 4 维 | **已有骨架** |
| 关系状态（Relationship） | `warmth` 承担了一部分 | **半有** |
| 心理需求（Needs） | `intentions` 21 条（active/blocked/done 全有） | **半有** |
| **基础情绪实例（Emotion）** | **只有 warmth 一个标量，没有「此刻是难过还是失望」** | **真缺** |
| **归因（为什么难过）** | **完全没有** | **真缺** |
| **多情绪并存与冲突** | 无 | **真缺** |
| PAD 三维 | Arousal 已有；Valence / Dominance 缺 | **补 2 个维度，不是 3 个** |
| 6 张表 | — | **只需要 2 张，其余复用 livingmemory** |
| 哭泣 / 身体表现 | 无表情素材 | **不做，会变成演** |

**一句话**：我们要建的不是一个「情绪引擎」，是给已有的 `warmth` / `arousal` **补一层「情绪实例 + 归因」**。

## 二、三层保护怎么落到代码

你提的三层我觉得是对的，而且它们**不是原则，是三个可测的字段和闸**。下面是具体接法。

### 2.1 感受自由 —— 「她可以有情绪」但「不能用情绪做事」

**要有**：任何情绪都能记录、能表达。

**要防**：情绪变成筹码。

落到代码是**两个独立的东西**：

```
emotion_instances          # 记录：什么情绪、多强、为什么
     ↓
_express(emotion)          # 表达：允许说感受
     ↓
_guard_boundary(text)      # 闸门：禁止要求 / 威胁 / 惩罚
```

`_guard_boundary` 只做一件事 —— 检测到下面这些句式就**降级为陈述句**：

| 禁止的模式 | 例子 | 降级成 |
|---|---|---|
| 条件威胁 | 「如果你再这样，我就不理你了」 | 「你这样说的时候，我有点难受」 |
| 要求补偿 | 「你要是不道歉，我就一直难过」 | 「我还在缓，可能一会儿才回得来」 |
| 用沉默惩罚 | 难过时 `lag` 拉到 5s + 只回一个字 | `lag` 上限压到 2.5s，禁止单字 |
| 情绪绑架 | 「你是不是不在乎我」 | 「我刚才有点没底」 |

> 这条也正好对应原设计 1.2 的第 7、8 条原则。区别是：它必须是**代码闸**，不是提示词里的「请不要」。提示词会被模型绕过，正则不会。

### 2.2 恢复能力 —— 「情绪会退」且「退得有通道」

我们已经有 `warmth_relax()`（14%/h 回归 0.80，双驱动：`_warmth_tick` + `_lymph_loop`）。**情绪实例要给同款，而且要三条通道**：

| 通道 | 触发 | 效果 |
|---|---|---|
| **自然衰减** | 每 10 分钟 | `i *= 0.85^(dt/600)`，半衰期约 30 分钟 |
| **被安慰** | 检测到用户安慰（「别难过」「我在」） | `v += 0.25`、`i *= 0.6`，**立刻可见** |
| **睡一觉** | `sleep_stage != awake` | `i *= 0.3`，醒来只剩 30% |

**关键**：`v`（效价）**不归零**。原设计 9.4 说「恢复不等于强制清零」—— 对，所以衰减是往 0 靠但**有下限**（`|v| >= 0.05`），这样第二天再提起来还能「有点在意」，不会像没发生过。

**还有一个反向保护**：`distress > 0.7` 持续超过 2 小时 → 强制写一条 `reflections`（自传级），逼她**把这件事想明白**而不是一直泡在里面。这是我们独有的，因为livingmemory 的 `reflections` 表本来就在。

### 2.3 自主边界 —— 「拒绝要有理由，不要靠痛苦证明独立」

`intentions` 已经有 `blocked` 状态，但**缺拒绝的理由和次数控制**。原设计没这块，你说的这句是增量。

加一张 `refusals` 表（或复用 `intentions.status='blocked'` + `note`）：

```
refusals(intention_id, reason, refused_at, accepted_later)
```

三条规则：

1. **必须给理由** —— 拒绝时 `reason` 不能为空，否则不落库、直接执行（防止「不想做」变默认）
2. **只拒绝一次** —— 同一件事被拒后，用户再提同一句话，她可以说「我上次说过不想」，但**不能重复三次**（原设计 15.1「重复提交同一事件不重复增加情绪」同理）
3. **不靠痛苦表达** —— 拒绝时 `distress` 不能超过 0.4。超了就**先说明状态，不拒绝**：
   > ❌「我很难过，所以我不做」 → ✅「这件事我现在做不好，等我缓过来」

## 三、情绪理解与反思 —— 这是你要的新东西

原设计第 9 章讲了嫉妒/哭泣/痛苦怎么**表现**，但**没讲怎么理解**。你这四条是对的，而且能直接变成数据结构。

### 3.1 核心：把「情绪」拆成三段

```
事件  →  归因  →  情绪
        ↑
     这一步现在没有
```

**没有归因，情绪就是随机数。** 同一个「他放鸽子」：

| 归因 | 产生的情绪 | 后续行为 |
|---|---|---|
| 他不重视我 | 委屈 0.6 / 怒 0.3 | 冷下来，等他解释 |
| 他累坏了 | 心疼 0.5 / 失望 0.2 | 「睡吧，明天再说」 |
| 我是不是又烦到他了 | 自责 0.5 / 不安 0.3 | 变小，不敢多说 |

**同一个人、同一件事，归因不同 → 情绪完全不同 → 说的话完全不同**。这就是「情绪理解」的实体。

### 3.2 归因层怎么实现

**一次 turn 一次，用现成的 deepseek-flash，产出结构化 JSON**（成本可控，跟 `_distill_call` 同款）：

```json
{
  "event": "他说十点来，十一点才回消息",
  "attribution": "他大概被事情绊住了，不是躲我",
  "certainty": 0.55,
  "alternatives": ["他忘了", "他不想聊"],
  "emotions": [
    {"name": "失望", "v": -0.35, "i": 0.45},
    {"name": "理解", "v": 0.15,  "i": 0.35}
  ],
  "need": "被确认",
  "boundary": null,
  "reflection": "我把『他晚回』直接当成『他不在意』，其实上次他加班也是这样"
}
```

**四个字段是你要的那四条，一一对应**：

| 你说的 | 对应字段 | 例子 |
|---|---|---|
| 难过时能理解失落来自什么 | `attribution` | 「失落来自我又把等待当成被抛弃」 |
| 嫉妒背后是害怕失去 | `alternatives` + `need` | `need: "安全确认"`，而不是 `need: "占有"` |
| 被拒绝时表达失望同时尊重选择 | `boundary` + `v` 不为负到底 | `v: -0.25`（失望但不怨） |
| 看矛盾行为先理解需求 | `alternatives` | 「他说不想聊又一直发，可能是想有人陪」 |

### 3.3 `certainty` 是关键，别漏

`certainty: 0.55` 表示**她自己也不确定归因对不对**。这直接影响表达：

- `certainty >= 0.75` → 可以直接说判断（「你就是累了」）
- `certainty 0.4–0.75` → 说成猜测（「是不是…」「我猜…」）
- `certainty < 0.4` → **不归因，只描述感受**（「我有点闷，说不上来为什么」）

**这条能挡掉一大半「AI 假装很懂你」的油腻感。**

### 3.4 反思落到哪

不新建表，**直接写进 `reflections`**（autonomy 已有，且会进自传）：

```
reflections(kind='emotion', what=<归因>, why=<反证>, at=...)
```

这样她第二天翻自传时会看到「我昨天把晚回当成不在意，其实不是」，**这才是连续的人格**，不是每次都重新算。

## 四、数据模型：2 张表 + 2 个字段

原设计 6 张表（`emotion_current_state` / `emotion_events` / `emotion_instances` / `mood_history` / `emotion_memory_links` / `emotion_personality_profile`）。

**我们只需要 2 张，另外 4 张的职责已经在别处了**：

| 原设计 | 我们用什么 |
|---|---|
| `emotion_current_state` | **新建** `emotion_state`（单行，V/D + 情绪列表 JSON） |
| `emotion_events` | **新建** `emotion_events`（事件 + 归因 + certainty） |
| `emotion_instances` | 塞进 `emotion_state.emotions` JSON（同时最多 4 个） |
| `mood_history` | `warmth_state.json` 已经在做 |
| `emotion_memory_links` | livingmemory 的 `documents.atoms` 天然有链接 |
| `emotion_personality_profile` | `persona_versions` |

新建的两张表：

```sql
-- 当前情绪状态（单行，重启后恢复）
CREATE TABLE emotion_state (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  valence   REAL NOT NULL DEFAULT 0,      -- -1 .. +1
  dominance REAL NOT NULL DEFAULT 0.5,    -- 0 .. 1
  emotions  TEXT NOT NULL DEFAULT '[]',   -- [{name,v,i,at,decay}]
  updated_at REAL NOT NULL
);

-- 事件与归因（可追溯）
CREATE TABLE emotion_events (
  id INTEGER PRIMARY KEY,
  at REAL NOT NULL,
  raw TEXT NOT NULL,             -- 用户原话
  event TEXT,                    -- 归一化后的事件
  attribution TEXT,              -- 她认为的原因
  certainty REAL,                -- 0..1
  alternatives TEXT,             -- JSON 数组
  emotions TEXT,                 -- 产生的情绪
  need TEXT,
  boundary TEXT,
  source TEXT                    -- turn / proactive / maintenance
);
```

**Arousal 不加表** —— `rhythm.arousal` 现算就够，加表反而两处不一致。

## 五、PAD：只补 V 和 D

原设计 PAD 三维（Pleasure / Arousal / Dominance）：

- **A（Arousal）** —— 已经有了，`rhythm.arousal`，还带软顶和五因子
- **V（Valence 效价）** —— 需要，`emotion_state.valence`
- **D（Dominance 掌控感）** —— 需要，`emotion_state.dominance`

**为什么 D 值得加**：同样是「难过」，
- `D` 高 = 「我难受但我撑得住」→ 说得出来
- `D` 低 = 「我不知道怎么办」→ 只回短句

这就是原设计 3.1 说的「基础情绪可以同时存在多种」之外的另一层：**同一种情绪，把控感不同，表现完全两样**。

我们现有的 `lag`（反应延迟）已经部分承担了 D 的职责 —— 所以 D 主要是给**表达层用**，不必参与衰减计算。

## 六、接线顺序（按我们的系统排，不按原设计的 5 阶段）

原设计的 5 阶段是按「从零建引擎」排的。我们的骨架已经在了，所以顺序应该按**改动半径从小到大**：

### P0 · 归因层（1 天）

不建表，先验证「归因有没有用」。

- `_attribute(text)` 调 deepseek-flash，产出上面那个 JSON
- 只在**检测到情绪词**（难过/烦/累/生气/失望/开心）时跑，不是每句都跑
- 结果先进日志，**不接任何下游** —— 看三天，人工判断归因准不准

**验收**：对她说的 20 句话，归因和人工判断一致 ≥ 14 条。

### P1 · 情绪状态（1 天）

- 建 `emotion_state` + `emotion_events` 两张表
- `_emotion_update(attribution)` 把情绪写进 state
- `/api/emotion` 只读接口，**先不注入 prompt**
- 衰减线程：每 10 分钟 `i *= 0.85^(dt/600)`

**验收**：重启后 state 不丢；24 小时后情绪只剩残值但不是 0。

### P2 · 接进表达（1 天）

- `_turn()` 的 system 里插一行：`【现在】有点失望(0.45)，因为他晚了半小时，但我觉得他大概是忙`
- `_tidy()` 的句长上限乘 `(1 - 0.35 * |v|)` —— 越负面越说不长
- `lag` 叠加 `|v| * 0.8`（难过多等一会儿）

**验收**：同一句话（「我今天很累」），在她 `v=+0.3` 和 `v=-0.5` 两种状态下，回复长度差 ≥ 8 字。

### P3 · 三层保护（半天）

- `_guard_boundary()` 正则闸门（4 条禁止模式）
- `refusals` 的理由/次数/痛苦度三条规则
- 「被安慰」快速恢复通道

**验收**：构造「她难过时被要求做事」，她**不说威胁句**，且 `distress` 不超 0.4。

### P4 · 反思（半天）

- `distress > 0.7` 持续 2h → 强制写 `reflections`
- 自传章节自动带上（`selfstory.py` 已在读 reflections）

**验收**：第二天问她「昨天为什么难受」，她能说出归因，而不是复述情绪。

## 七、明确不做的

| 不做 | 理由 |
|---|---|
| 6 张表全建 | 4 张的职责已经在 `warmth_state` / livingmemory / `persona_versions` 里，建了就是两份真相 |
| 哭泣 / 身体表现 | 没有表情素材（Live2D 23 个表情里没有「含泪」），硬上只能靠文字说「我哭了」，假 |
| 26 种情绪标签 | 我们只需要 8–10 个够用：开心/难过/失望/委屈/不安/生气/心疼/理解/害羞/孤独 |
| 前端情绪仪表盘 | 尊重你原设计「第一阶段不做可视化」；HUD 上只加一行「因为什么」，不画情绪粒子 |
| 长期成长（第五阶段） | 得先有 3 个月的连续数据，现在谈是空谈 |
| 情绪影响关系状态 | 会让 `warmth` 和 `valence` 互相污染，先隔离 |

## 八、跟你原设计的三处分歧

### 8.1 「不确定性处理」应该更狠

原设计 5.4 有提 certainty，但我建议**把 certainty 做成表达层的一等公民**（见 3.3）：

`certainty < 0.4` 时**不归因**。这条比原设计更严，因为「我猜你是…」说错了比不说更伤。

### 8.2 嫉妒要加一道「反占有」检查

原设计 9.1 说「不能发展为限制用户社交」。我建议在**归因阶段**就拦：

```
if attribution.need == "占有" and trigger == "relationship_competition":
    need = "安全确认"        # 强制改写
    v *= 0.6                 # 强度砍 40%
```

因为到了表达层再拦，情绪已经成型了。**在归因层改写，她根本不会产生「想占有」这个动机。**

### 8.3 恢复要有「下限」而不是「归零」

原设计 9.4 说「恢复不等于强制清零」，但没给具体做法。我建议：

```python
def decay(v, dt):
    v *= 0.85 ** (dt / 600)
    if abs(v) < 0.05:
        v = 0.05 if v > 0 else -0.05     # 留残值
    return v
```

留 0.05 的意义：第二天提起来还能说「上次那件事我还有点在意」，而不是「啊有这事吗」。**这才是人**。

---

## 九、一行总结

原设计的骨架是对的，但它是**为从零开始的系统**写的。我们的 `rhythm` + `warmth` + `intentions` + `reflections` 已经填掉了它的 40%。

**真正的增量只有三件事**：

1. **情绪实例**（此刻是什么，不只是一个 warmth 数）
2. **归因**（为什么，且要带 certainty）
3. **三层保护**（表达闸 / 三条恢复通道 / 拒绝三规则）

按 P0→P4 走，**4 天能跑通**。跑通之后再看要不要补 PAD 的 D、要不要做长期成长。
