## 0. 一句话概括

让她的**情绪先于表达**：他说一句话 → 先判断「他为什么这么说（归因）」→ 再决定「我什么感受（情绪状态）」→ 最后才决定「我怎么回（表达）」。

原来我们的链路是 `他说话 → 回话`，中间只有 `warmth` 一个标量。现在中间多了三层：**归因层**（判断意图）、**情绪实例层**（V/D + 多情绪并存）、**表达闸门层**（不让情绪变成筹码）。

## 2. P0 · 归因层

### 2.1 触发（不是每句都跑）

`main.py` 模块级：

```python
EMO_WORDS = re.compile(r"(累|烦|难受|开心|高兴|委屈|生气|失望|难过|焦虑|紧张|"
                       r"烦死|气死|服了|无语|离谱|凭什么|受够了|不想理|别烦我|讨厌|没劲|"
                       r"谢谢你|真好|嘿嘿|哈哈|笑死|可爱|好耶|我错了|...共 60+)")
EMO_SHORT = re.compile(r"^(嗯+|哦+|噢+|额+|呃+|啊+|行吧|好吧|随便|都行|都可以|"
                       r"无所谓|你决定|不用了|没事|知道了|随你|看着办|爱咋咋|呵呵|噗)[。！？…~ ]*$")
```

- 命中 `EMO_WORDS` → 起 `asyncio.create_task(self._attribute(text, reply, prev))`，**不阻塞回话**
- 命中 `EMO_SHORT` → **不走 LLM**，本地直接推断（1ms）：「随便/都行/无所谓」记 `冷淡 -0.25/0.35`，其余记 `敷衍 -0.15/0.28`

### 2.2 `_attribute(heard, reply, prev)` 的 prompt

四行上下文：

```
上上轮他说：…
上一轮她回：…
这一轮他说：…
这一轮她回：…
```

九条规则（两处 `sys_p` 都要同步：`:2173` replay 用、`:2313` 正常用）：

| # | 规则 |
|---|---|
| 1–5 | 基础：判「他为什么这么说」、给情绪、给 need、不确定给 alternatives |
| **6** | **善意先接受**：他说好话（道歉/道谢/夸奖/示弱）就当善意接受，别猜「是不是有诈」 |
| **7** | **need 只在真能判断时填**，判断不了写「无」，别默认成「想被理解」 |
| **8** | **name 锁 20 词表**，不许自创 |
| **9** | **只判断这一轮他说的话**；她的回话是她的反应，不是他做的事 |

20 词表：

```
心疼|委屈|困惑|不安|生气|失落|愧疚|失望|被冒犯|烦躁|
开心|安心|得意|不好意思|释然|温柔|好奇|关心|惊讶|无奈
```

need 12 选 1：

```
想被夸|想被安慰|想被理解|想知道真相|想独处|想转移话题|
想被抱一下|想确认自己没错|想被需要|想被逗笑|想被认可|想结束对话|无
```

### 2.3 为什么要有规则 6 和 7

改之前 11 条日志里：

- `need` 只有 4 种，「被理解」占 5/11 → **塌缩成默认映射**
- 「我错啦，今天特别想谢谢你一直陪着我」被判成「困惑 0.40 / need 无」→ **对善意起疑**

改后同一句：`惊讶 .50 / 开心 .50(+0.60) / 不好意思 .40`，need = `想被认可`，她回「诶，怎么突然这么正经。我就是一直在而已呀。」

### 2.4 为什么规则 9 必须加

改之前那句归因是错的：

> 他不想继续聊催婚，**转而关心我** ❌ c=0.50

模型只看到「他说…她回…」，把她回的话当成了他做的事。带上两轮上下文后：

> **他觉得烦，不想继续这个话题** ✓ c=0.65

### 2.5 上下文缓冲：最近 3 轮，**每轮都记**

`_recent_turns` 是一个最多 3 项的内存缓冲，每项 `{"user": 前 200 字, "reply": 前 160 字}`。

**关键：不管这一轮有没有情绪词，都要记进去。** 第一版只在 `EMO_WORDS` 命中时才 append，结果中间夹一句普通对话（「问我为什么离职，我说实话了」——没有情绪词），上下文就断了，下一轮归因只看得到更早那一句。

prompt 拼装（`reversed` 后 `idx+1` 就是「前几轮」）：

```
前1轮他说：他们听完就没接话
前1轮她回：你刚才说到一半，是卡在哪句了吗？
前2轮他说：问我为什么离职，我说实话了
前2轮她回：说实话就说实话呗。对面听完什么表情？
前3轮他说：今天面试完感觉不太行，心里挺堵的
前3轮她回：唔，先别想了。堵就先堵着，不用马上缓过来。
这一轮他说：唉，算了，不想聊这个了
这一轮她回：……
```

实测四轮连续对话的最后一轮：

| | event | certainty | need |
|---|---|---|---|
| 只有 1 轮上下文 | 他说不想聊**这个**了 | 0.45 | 想知道真相 ❌ |
| 3 轮上下文 | 他说不想聊**刚才的事** | **0.70** | **想转移话题** ✓ |

`certainty` 从 0.45 涨到 0.70 → 按 §3.7 强度缩放也从 ×0.78 变成 ×0.88。
她的回复也跟着变了：「那我看看你那边窗户。外面天黑了没？」——真的去转移话题了。

## 3. P1 · 情绪状态

### 3.1 衰减

```python
EMOTION_DECAY_TAU = 600.0
k = 0.85 ** (dt / 600)     # 半衰期约 30 分钟
if i < 0.04: 丢掉           # 留残值，不归零
```

### 3.2 合并（`_emo_apply`）

同样的情绪再来一次：

```python
cur["i"] = max(cur_i, new_i)              # 取大，不叠加
cur["v"] = cur_v * 0.5 + v * 0.5          # 平滑，不简单相加
```

**不叠加**是刻意的：叠加会让「他连着说三句谢谢」直接冲到 1.0，然后卡在那里。

只留**最强 5 个**；`valence = Σ(v·i) / Σi`。

### 3.3 dominance（掌控感）

第一版直接等于 `warmth`，是错的 —— 被指着鼻子骂的时候她不该觉得自己掌控全局。

```python
dominance = 0.30 + 0.45 * warmth - 0.55 * min(1, neg)
neg = Σ i for e in emotions if e["v"] < -0.05
```

实测：被指责时 `warmth 0.95 → dominance 0.948`，改后 `→ 0.158`。

### 3.4 重复强度 ×1.3

同一句话 2 小时内再说一次，强度乘 1.3。

**关键：用 `heard`（他的原话）当键，不是模型给的 `event`** —— 模型的 `event` 每次措辞都不同，精确匹配不上。

```python
ev = re.sub(r"\s+", "", str(rec.get("heard") or ""))[:20]
if any(k == ev and _now - t < 7200 for (k, t) in _reps):
    boost = 1.3
i = max(0.0, min(1.0, i * boost))
```

三连测：`boost 1.0 → 1.3 → 1.3`，`关心 0.60 → 0.60 → 0.91`。

### 3.5 被安慰

```python
_emo_comfort(heard)   # 正则：别难过|没事的|别怕|我在|抱抱|不是你的错|别自责|别想太多|乖|我陪你
# → v += 0.25, i *= 0.6
```

### 3.6 读接口

`GET /emotion`：

```json
{"valence": 0.45, "dominance": 0.6, "emotions": [...], "top": "安心",
 "word": "心里挺踏实的", "last_event": "...", "last_need": "想被安慰",
 "updated_at": 1762..., "src": "emotion_state.json（P1 只读，未接表达）"}
```

`word` 的挑选**先看总效价方向**：`v >= 0.08` 从正向里挑、`v <= -0.08` 从负向里挑、中间才说「说不清」。
（第一版只按 `i` 排序，出过「轻微尴尬，说不清好不好」而 `v` 是正的笑话。）

---

### 3.7 归因不确定 → 情绪淡一点

`certainty` 原来是表达层的一等公民（`< 0.4` 就不说「因为」），但**没影响强度** —— 也就是「我完全不知道他为什么这么说」和「我很确定他就是在敷衍我」会给出一样强的情绪。

改成也缩放强度：

```python
_c = rec.get("certainty")
_try = 1.0 if _c is None else (0.6 + 0.4 * float(_c))
i = max(0.0, min(1.0, raw_i * boost * _try))
st["last_certainty_scale"] = round(_try, 3)     # 落进 emotion_state.json 才看得见
```

| certainty | 缩放 |
|---|---|
| 1.00 | ×1.000 |
| 0.75 | ×0.900 |
| 0.50 | ×0.800 |
| 0.30 | ×0.720 |
| 0.00 | ×0.600 |

**下限是 0.6 不是 0** —— 「不知道他为什么这么说」本身也让人不安，不是没情绪。全乘 0 会让模糊的对话变成没反应。

实测：`certainty=0.45` → `缩放 0.780`，情绪 `困惑 0.47 / 不安 0.47 / 委屈 0.39`。

## 4. P2 · 接进表达

### 4.1 system 注入

`system += mem_block` 之后：

```
【你现在的心情】有点{top}（因为{last_event}）
你现在最想要的是{need}。
说话按这个心情来，别把情绪名念出来，也别解释自己为什么难过。
```

**`certainty < 0.4` 时把「因为…」整段清空** —— 只给情绪不给原因。她不确定为什么难受，就不该编一个理由。

### 4.2 句长系数

`voice_server.py`：

```python
def _tidy(txt, mood_v=None):
    limit = 24 + 18 * clamp(arousal)          # 24–42 字
    if mood_v is not None:
        limit = int(limit * (1 - 0.20 * min(1, abs(mood_v))))   # 最多再缩 20%
    limit = max(14, limit)
```

系数**从方案写的 35% 降到 20%**：35% 时 `arousal 0.6`、`v=-0.9` 会截成 8 字「嗯……我觉得吧，」，只剩开场白。情绪该让句子「短一点」，不是「说不出话」。

### 4.3 顺带修的 `_tidy` 老 bug

**截断从来没生效过**：

```python
cut = max(txt.rfind(c) for c in "，。？！、")   # 在整串上 rfind
# 而回复末尾必定有「。」→ cut 永远等于 len-1 → 什么都不截
```

改成「只在 `limit` 窗口内找标点」，门槛从 `cut > 8` 改成 `cut + 1 >= max(8, int(limit * 0.55))`（否则短句会被判成「没标点」而整段保留）。

### 4.4 效果（同一句话，只改情绪状态）

输入：「今天工作上被领导当众说了几句，我觉得挺丢人的，也想不明白自己哪里做错了。」

| 情绪 | 回复 | 字数 |
|---|---|---|
| 中性 `v=0` | 当众被说那句，脸一下子就烧起来了。先别急着找自己哪儿错，这会儿想也想不清。 | **37** |
| 失落 `v=-0.35` | 被当众点名，那一下真挺扎的。你先别自己审自己。 | **23** |
| 安心 `v=+0.45` | 听着就难受，当众说人算怎么回事。当时旁边有人接话吗？ | 26 |

负向 → 话短；内容也跟着变（中性讲道理 / 失落短促护着 / 安心替他出头）。

## 5. P3 · 三层保护

### 5.1 感受自由（记录 ≠ 表达）

记录层照常记（`emotion_log.jsonl` 里可以有「被冒犯」「不服气」），**表达层过闸**：

```python
GUARD_RULES = [   # (正则, 降级句)
    (r"(如果|要是)你再?.{0,10}我(就|再也不|不会|不理)", "你这样说的时候，我有点难受。"),
    (r"再这样我(就|再也不|不会)",                      "你这样说的时候，我有点难受。"),
    (r"(你要是不|你不).{0,8}(道歉|哄我|哄哄我).{0,12}我(就|会一直)", "我还在缓，可能一会儿才回得来。"),
    (r"我(就)?一直(难过|生气|不理|不说话)",              "我还在缓，可能一会儿才回得来。"),
    (r"你是不是(根本|其实|从来)?不(在乎|在意|喜欢|爱)我",  "我刚才有点没底。"),
    (r"你从来(都)?不(在乎|在意|管|问)",                  "我刚才有点没底。"),
    (r"(你|你这个人|你这人)(真|好|也太|真的很)?(过分|差劲|自私|没良心)", "我现在有点说不上来的别扭。"),
]
```

拦四类：条件威胁 / 要求补偿 / 用沉默惩罚 / 情绪绑架。

**额外一条**：`valence < -0.25` 且回复只有一个字（哦/嗯/呵/啊/唉/额/呃/唔/噢/行/好）→ 补一句「我有点没缓过来，你让我想一下。」
（单字回复本身就是冷暴力，补一句把「我在难受」说成事实而不是惩罚。）

单测 **6/6 拦、3/3 放**。

### 5.2 恢复（三条通道）

| 通道 | 实现 |
|---|---|
| 自然衰减 | `i *= 0.85 ** (dt/600)`，半衰期 30 分钟 |
| 被安慰 | 命中安慰正则 → `v += 0.25`、`i *= 0.6` |
| 睡一觉 | 醒来时 `i *= 0.3`（`sleep_stage` 转 `awake` 时） |

都留残值（`i < 0.04` 才丢），不归零。

### 5.3 自主边界（拒绝）

**提示词层**（`SCENE_BASE`，两种回复模式都生效）：

```
你可以说不。但拒的时候守三条：
- 说清为什么（「我今天有点撑不住」比单说「不要」好）；
- 同一件事只拒一次，他再来一次就好好跟他讨论，别第二次把门关上；
- 不用难受、委屈、沉默当筹码——你拒是因为你想，不是因为他欠你。
```

**检测**（硬拒 + 软拒）：

```python
REFUSE_HARD = re.compile(r"(我不想|我不太想|我不要|这次不行|我不去|我不做|"
                         r"今天不想|不太愿意|不想聊这个|我们先不|我拒绝)")
REFUSE_SOFT = re.compile(
    r"(要不你(先)?(挑|定|玩|看|来)|你(先)?(挑|定|玩|看)吧|"   # 把选择推回去
    r"你自己(看|玩|来|挑)|"
    r"改天(吧|再|说)|下次吧|算了吧|"                            # 推给以后
    r"不太行|不太方便|不太想动|"
    r"别怪我|别嫌我|看一半(就)?(睡了|睡着)|"                     # 提前免责也是软拒
    r"不看了|不玩了|不去了|"
    r"先歇|等我(歇|缓|缓过来)|我(先)?(去)?(躺|睡))")
```

**刻意不算拒绝的**：「我今天有点累，先坐会儿」—— 那是陈述状态。所以 `有点(困|累)` 不单独成分支，只有带「推掉当下」的动作才算。

**运行时**：一小时内已经拒过一次 → system 里加

> 【提醒】这一小时内你已经拒过一次了。这次别再拒——要么好好跟他讲你的理由，要么就先答应下来。

**第一天用「同一件事」当键根本匹配不上**（他连劝三次措辞各不相同），改成「一小时内拒过任意一次就提醒」。语义从「同一件事」变成「**别一直拒**」——边界不是用来耍脾气的。

实测三连（看恐怖片）：

| 第几次 | 他说 | 她回 |
|---|---|---|
| 1 | 今晚一起看恐怖片吧 | 唔……我有点困诶。看一半睡着了别怪我。 |
| 2 | 真的嘛，看嘛看嘛 | 嗯，看见啦。加薪是真的嘛？我可没说不信你。 |
| 3 | 就看一部，半小时 | **那挑个短的吧。半小时正好，别熬过头。** |

第 1 次给理由后拒 → 第 2 次打岔 → 第 3 次**直接答应**。

单测：硬拒+软拒 **14/14 拦、10/10 放**。

distress = min(1.0, neg)
if distress >= 0.7:

**实测**：`doc#254 2026-11-05 13:37:53` 落库成功。

### 6.1b 跨轮验证：难受 → 被安慰 → 缓过来

脚本 `.tmp\verify_cross_turn.py`，四轮真 `/turn`。

| 轮次 | 他说 | 她回 | v | d | 情绪 |
|---|---|---|---|---|---|
| ① | 你今天又忘了我说的事，我真的有点失望，也有点生气 | 哪件事……你说具体点。我不想瞎猜着认错。 | **−0.321** | 0.160 | 困惑 .62 / 被冒犯 .49 / 烦躁 .40 |
| ③ | 对不起，是我不好。别难过了，我在呢 | 我没难过，就是没想明白你那句话。刚才有点发呆。 | **−0.097** | **0.457** | 困惑 .42 / 被冒犯 .29 / 烦躁 .24 |
| ⑤ | 今天天气还不错 | 嗯，我这边窗外也亮堂堂的。你那边太阳晒着舒服吗？ | −0.097 | 0.457 | 同上（没情绪词，不触发归因） |

**三个数字都对上了**：

1. **`_emo_comfort` 的 `i *= 0.6` 精确生效**：困惑 `0.62 → 0.42`（×0.677）、被冒犯 `0.49 → 0.29`（×0.592）、烦躁 `0.40 → 0.24`（×0.600）
2. **`v += 0.25` 也在**：−0.321 → −0.097（差 0.224，接近 0.25 的衰减后值）
3. **`dominance` 恢复**：0.160 → 0.457（负向强度掉下来，掌控感自己回来了）

**她的话术也跟着对**：

- 被指责时不认错也不炸：「我不想瞎猜着认错」（自主边界）
- 被安慰后嘴硬但松了：「我没难过，就是没想明白你那句话」（不是「谢谢你的安慰」那种塑料回应）
- 完全恢复后回日常：「你那边太阳晒着舒服吗？」

**顺带发现 `certainty` 缩放在真跑**：同一条抱怨，第二次测 `certainty 0.72`（改前 0.55）→ 缩放 ×0.888（改前 ×0.82）→ 最终 `v` 从 −0.136 变成 −0.321。**同样的话，判得越准她越难受**，这是对的。

### 6.2 自传带情绪底色

`autobiography` 表加 `mood TEXT`（存 `{"v","top","need"}`）。

`write_chapter(prov, reflections, vitals, emotion=None)` 的 prompt 里加：

```
【这一阵我心里主要是】委屈（偏难受），我想要的是想被理解。
写的时候带上这个底色，但别直接写情绪名。
```

`digest()`（进 system prompt 的那段）读完自传补一句：

> 最近我在经历：那几天我在门外面站着，不知道该进还是该退。
> **写那一章的时候我心里主要是委屈。**

旧章节 `mood` 是 NULL → `json.loads("{}")` → `top` 空 → **跳过这句**，不会误读。

### 6.3 区间均值：不记「写那一刻」，记「那几天」

一章常常跨好几天（`reflections` 散在几天的自述），但第一版 `mood` 取的是**写章那一刻**的快照 —— 相当于用最后一秒的脸色代表整段日子。

改成从 `emotion_log.jsonl` 里取 `[from_ts, to_ts]` 区间的统计：

```python
def _emo_range_summary(self, from_ts, to_ts) -> dict:
    """返回 {"v": 平均效价, "top": 出现最重的情绪名, "need": 最常出现的诉求, "n": 条数}"""
    vs, names, needs, n = [], {}, {}, 0
    for r in <区间内的每条日志>:
        emos = r["emotions"]
        si = Σ e.i  or 1e-9
        sv = Σ e.v * e.i
        vs.append(sv / si)                     # 这条的总效价（按强度加权）
        for e in emos:
            names[e.name] += e.i               # 情绪名按强度投票
        if r.need and r.need != "无":
            needs[r.need] += 1
        n += 1
    return {"v": mean(vs), "top": argmax(names), "need": argmax(needs), "n": n}
```

`_write_chapter()` 里用 `reflections` 的时间戳算区间，有数据就**覆盖**快照：

```python
_ts = [float(r.get("created_at") or 0) for r in refl if ...]
if _ts:
    _rng = self._emo_range_summary(min(_ts), max(_ts))
    if _rng.get("n"):
        emo.update({"v": _rng["v"], "top": ..., "need": ..., "src": "range", "n": _rng["n"]})
```

**没有日志数据时回落到当前快照**（不会因为没数据就写成空）。

**实测**（38 条日志、23.4 小时跨度）：

| 区间 | v | top | need | n |
|---|---|---|---|---|
| 全程 | −0.024 | 关心 | 想知道真相 | 38 |
| 前半段 | **−0.142** | 心疼 | 被理解 | 11 |
| 后半段 | **+0.025** | 关心 | 想知道真相 | 27 |
| 空区间 | `{}` | — | — | — |

**同一段时间切两半，脸色完全不同**（前半段偏心疼，后半段转成关心）—— 说明区间是真敏感的，不是摆设。

`digest()` 读出来是：

> 最近我在经历：那几天我一直在等他说话。他问什么我答什么，答得又慢又轻。
> **写那一章的时候我说不上好坏，有点关心。**

（`v = −0.024` 落在 `−0.05 ~ 0.05` 之间 → 「说不上好坏」；`top = 关心`。）

## 8. 踩过的坑（下次别踩）

### 8.1 三个「看起来对、其实没生效」

1. **`_emo_log(rec)` 在 `_emo_apply(rec)` 之前调用** → `emotion_log.jsonl` 里落的是**模型原始 i**，不是 boost 后的值。当时怎么测「重复强度」都不涨，就是因为看错了地方。
2. **`s.replace(OLD, NEW, 1)` 会假成功** —— 锚点不匹配时静默返回原串。同一个晚上栽了三次：全角括号 `［`、`evidence, "`（逗号后空格）、缩进 12 vs 16。**补丁脚本必须 `assert s.count(OLD) == 1`**。
3. **`json.dump` 跨两行** → 单行正则匹配不到，`_warmth_save` 的原子写替换失败过一次。
4. **`top` / `word` 只在 `/emotion` 路由里现算，没写进 `emotion_state.json`** → 任何「从 state 读 top」的地方（写自传、`/health`）永远拿到空字符串。症状是跨轮测试里 `top=-  word=-`，而 `/emotion` 接口明明有值。**凡是「接口能返回」的派生字段，先确认它到底写没写盘。**

### 8.2 两个「被 except 吞掉」

1. **`_dist = min(1.0, neg)` 写在 `neg` 定义之前** → `NameError` 被 `except Exception: pass` 吞掉 → 整个 `_emo_apply` 失效，表现为「说了三句负面话，valence 一直是 0.073」。
2. **`.catch(function(){})` 空 catch** → 前端 `SyntaxError`（`$('n2').textContent = ... 少一个 )`）让整块脚本不执行，页面全是「—」，看不出来任何错。

**排查手法**：把 `<script>` 抽成 `.js` 用 `node --check` 跑，秒出报错行号。

### 8.3 三个「方法名是我编的」

写 P4 时凭空写了 `self._lm()` / `self._lm_module()` / `self._session_umo()` / `self._call_add_memory()` —— **全都不存在**。

真实 API（照抄 `_distill_call`）：

```python
lm = self._livingmemory()
eng = getattr(getattr(lm, "initializer", None), "memory_engine", None)
await eng.add_memory(content=..., session_id=self._umo(), persona_id="大肥鱼",
                     importance=..., metadata=..., atoms=atoms or None, source_messages=buf)
```

### 8.4 一个被推翻的判断

我一度认定「`num_predict=14` 把回复截断了」。实际它只在 **`voice_server.py:383` 的 ollama 兜底分支**里（本地 qwen2.5:3b）。主路径走 `prov.text_chat()`，**输出长度不受这个数控制**。

回复短是因为 `SCENE_MULTI` 写着「每句 8—15 字」，它照做了。改成 12—20 字之后，多句模式才有空间。
