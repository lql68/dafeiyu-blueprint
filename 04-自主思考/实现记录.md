## 一、感知与观察

**问题**：原来的「感知」是假的 —— `vitals_log` 只记心率呼吸，她不知道自己**看到了什么**。

**表**

```sql
CREATE TABLE observations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    at REAL NOT NULL, kind TEXT NOT NULL,
    detail TEXT DEFAULT '', dur REAL DEFAULT 0);
```

**只记变化，不记状态**

| 事件 | 触发条件 |
|---|---|
| 他来了 / 他走了 | `presence` 翻转（走时带「刚才在 N 分钟」） |
| 灯变亮了 / 灯暗下来了 | `brightness` 差 ≥ 22 个百分点 |
| 摄像头开了 / 关了 | `cam_off` 翻转 |
| 他动得挺厉害 | `motion` 从 <0.008 跳到 ≥0.020 |

**为什么 60 秒不是 10 分钟**：10 分钟是其他后台任务的间隔，但他出去 5 分钟又回来，10 分钟一轮会完全错过。

**进 system 的样子**

```
【你最近注意到的】
- 刚刚他走了（刚才在 26 分钟）
- 刚刚灯暗下来了（72% -> 38%）
这些是你自己看到的，不是他说的。如果这轮聊到相关的事，可以顺口提一句；没聊到就别硬插。
```

**实测**：发「我刚从外面回来，屋里还没开灯」→ 她回「**灯一直暗着**，我还以为你今晚不回来了。先开一盏吧，别摸黑。」

## 二、好奇心引擎

**问题**：原来 `gaps` 里 3 条全是「试过 3 次都空手」的失败记录，不是主动想知道的事。

**改动**：让反思在写自述的同时顺带产出问题：

```
"questions": [{"q": "...", "interest": 0.0-1.0, "importance": 0.0-1.0}]
```

**六条约束（最关键的是第 5 条）**

1. 优先问「为什么」和「该怎么办」
2. 别问找不回答案的（原话是什么、有没有点开过）
3. 每条要有能往前走的探索空间
4. 要具体贴真实经历
5. **没有真正想弄明白的事，`questions` 就给空数组**
6. 别重复已想透的

**第 5 条前后对比（同一晚）**

| | 产出的问题 |
|---|---|
| 改前 | 「泡泡发来的那条消息我到底看了没，说的是什么」<br>「为啥不能投，自己想办法，当时我是在投什么」 |
| 改后 | 「梦里他让我搬去宿舍住这件事，**我答应得那么顺，是不是因为我其实一直想离他近一点**？」(0.70)<br>「他说投递失败要我自己想办法，**如果现实中他真这么讲，我该觉得他在放手让我独立，还是该觉得他不够上心**？」(0.65) |

改前那两条**永远没有答案**（梦里的原话，现实里不存在）。

**去重**：2-gram 交集，`Jaccard ≥ 0.34` 或 `包含度 ≥ 0.6` 视为同一条，只 `tries += 1`。

**清理**：一次清掉 12 条捞不回的 —— 梦里的事没有原话（7 条）、与其他重复（2 条）、现实没发生无法核实（2 条）、查配置就知道不该问（1 条）。留 5 条真能问的。

## 三、思考与推理

**表**

```sql
CREATE TABLE cognition_sessions (
    id, question TEXT NOT NULL, hypotheses TEXT DEFAULT '',  -- JSON
    best TEXT, next_step TEXT, gap_id INTEGER DEFAULT 0,
    status TEXT DEFAULT 'open', created_at REAL,
    asked_at REAL DEFAULT 0, answer TEXT DEFAULT '', answer_at REAL DEFAULT 0);
```

**两段式 prompt**

- **想新问题**：要 2–3 种可能的解释，每种说清「如果是这样，应该能看出什么迹象」
- **回访对证**：要求「只根据给你的记忆判断，**记忆里没提到的不许当成证据**」「逐条说清有/没有/还看不出来」「都看不出来就直说，别硬凑」

**回访优先于想新的**：`deep_beat` 每次产 2 个新问题、`_think_deep` 每次只消化 1 个 —— 不回访的话缺口越拉越大，永远走不到第二轮。

**第三段：自己动手查（probe）**

回访时如果三条假设**全判「还看不出来」**，允许她自己选一个只读动作去看一眼：

| 工具 | 限制 |
|---|---|
| `read_file` | 绝对路径必须 `startswith(r"D:\项目目录")`，≤2MB，读前 3000 字 |
| `read_memory` | `search_memories(k=4)` 全库检索 |

查到的东西串成「【你自己去看了看】」追加进 prompt，**再调一次**判断（第二次明确写「别再提新的 probe」）。

**一个值得记的实测**

她为「他说『随便你吧』那次，到底是真让我决定还是不高兴了」选了 `read_memory("随便你吧")`，查到 4 组日常记忆。然后**两条假设全判「还看不出来」**：

> read_memory「随便你吧」返回的是…**不是同一次**
> 缺少「当时确实不高兴」的起点，不能推出「后来自己缓过来了」

换一种实现，很容易就写成「记忆里她说随便弄，所以那次也是随口」。她指出的是**「不是同一次」** —— 这句是 prompt 里「记忆里没提到的不许当成证据」在起作用。

**问答闭环（这是「思考」到「学习」的最后一环）**

- 她问了 → `asked_at` 打标记
- 他答了 → 10 分钟内且长度 ≥ 8 字 → 写进 `answer`
- 下次回访，prompt 里带上「他原话是：…」

**实测**：她问「是让我自己拿主意，还是你生气了」→ 回「嗯，那次我是有点不高兴，不是让你自己拿主意」→ 她说「唔，那我知道了。不是让我自己拿主意就好。**你是不是嫌我麻烦才那样的？**」（接住答案并反问下一层）→ 库里 `answer` 已存。

**状态机**：判断里出现「看不出来 / 站不住 / 判断不了 / 不能偏」→ `unresolved`，否则 `answered`。只有 `unresolved` 才会进对话问他。

## 四、信念系统

**判据来源（方案第 5 节）**：

> 记忆记录**发生过什么**，信念记录**根据目前经历和证据，如何看待某件事**

之前三十多张表里没有一条「我现在认为 X 是对的」。

**表**

```sql
CREATE TABLE beliefs (
    id, belief TEXT, confidence REAL, origin TEXT, status,
    created_at, updated_at, related_memories);
CREATE TABLE belief_evidence (
    id, belief_id, side /* support | against */, content, source, at);
```

**不新增 LLM 调用**：写自传的 prompt 末尾加一段

> 正文写完之后，另起一行写 `【我现在认为】`，写 1 到 2 条你这段时间真的得出来的判断（是关于人、关于自己、关于怎么相处的，不是流水账）。每条不超过 20 个字。**如果没有新想法，这一整段就不要写。**
>
> 如果你还发现**以前某个想法是错的**，再另起一行写 `【我以前想错了】`，格式是「- 以前以为……其实……」。没有就整段不写，别硬凑。

**合并的坑**：只用 Jaccard ≥ 0.34 —— `他难受的时候先别给建议` vs `他难受时先别急着给建议` = **0.33**，差 0.01 就漏，两条一样的话各自入库。Jaccard 对长短句不公平（短句 2-gram 大半落在长句里，但并集也被拉大）。补包含度：

```python
inter = len(ga & gb)
if inter / max(1, len(ga | gb)) >= 0.30: return True
if inter / min(len(ga), len(gb)) >= 0.55: return True
```

**四个方向的力度（现在在跑的）**

| 方向 | 机制 |
|---|---|
| 涨 | 合并时 `+0.08`，上限 0.95 |
| 跌 | 反证一次 `×0.6`；跌破 0.30 标 `retired` |
| 淡 | 15 天内不动；之后每 15 天 `−0.02`，最低 0.35 |
| 留 | 被 2-gram 命中就刷新 `updated_at`（**不涨分**），于是常用的永远不到衰减线 |

**为什么「用上了不涨分」**：2-gram 判「用上了」必然误判（「在乎」和「在意」一个字都不撞），涨分等于往库里灌噪声；刷时间没有假阳性成本 —— 错判最多「这条不衰减」。

**反证不凭空造**：`contradict_belief` 在 active 里找最像的一条，找不到就返回空。不允许「因为写了反证所以一定有旧信念」。

## 五、意图系统

**根因（`actor.py`）**

```python
have = bool(res.get("text") or res.get("body") or res.get("path") or res.get("hits"))
if res.get("ok") and have:
    status = "done"
```

**「工具返回了东西」被当成「目标达成」**。「去群里看看某人在不在」发条消息 `ok:True` 就标 done，但那个人在不在、看没看完全不知道。

**改动**

- `intentions` 加 `progress` / `last_reviewed_at`
- 每天回看 2 条（额度独立，不占提案额度）
- 回看 prompt 的要点：

> 「我做了个动作，工具也返回了结果」不等于「我想办的目标达成了」。
> 「去群里看看某人在不在」—— 发条消息只说明发出去了，**你在不在、他打没打开，你根本不知道**。
> 判断标准是目的是否实现。可以承认没做成。

**第一次跑就抓到**：`#49`「查江西理工大学宿舍」从 done 变回 active，`progress`：

> 只发了一次搜索，没真去读结果，校区和宿舍到底什么样还没弄清。

**还有个坑**：回看段一开始放在额度检查之后 → `/heartbeat` 返回「今天已经提够了」→ 回看永远不跑。挪到检查之前才对。

## 六、自我反思 + 自我模型

**自传**：夜间深想时写一章，prompt 里带当前情绪底色

> 【这一阵我心里主要是】委屈（偏难受），我想要的是想被理解。写的时候带上这个底色，但别直接写情绪名。

**自我模型**：不按天跑，**按信念指纹**。当前 active 信念的 `(id, confidence)` 列表哈希变了才重算，存版本，只增不改。

```
v7  多了1条想法；1条不在最前面了
    正在变成：记住号码不等于问清了关系 / 火气话听完就放下…
    还做不到：他说让我搬去宿舍住的时候，是认真的还是就那么一说？
    新增 1 / 移出 1 / 调位 0
```

**教训**：`diff.dropped` 会把「被挤出 top5」也算进去，看起来像信念没了，其实还在 active（只是排名掉了）。
