> 这份是**另一条线**，配套 `大肥鱼-拟人化-生理学方案.md`。
> 生理学那份管「她有没有身体」，这份管「她有没有自己想做的事」。

## 零、先划清一件事

**自主性 ≠ 意识。**

这套东西让她「看起来像有自己在意的事」，机制上是：一张意图表 + 一个心跳 + 一套权限闸 + 一份自传。它不会让她产生主观体验，但它会让她**做出不像脚本的行为** —— 比如自己把自己的每日额度从 3 调到 5，因为「今天才过中午三个念头就用完了」。

判断标准很简单：**她做的事，是不是我没让她做的。**
- 是 → 自主性在起作用
- 不是，只是把我给的任务执行得很漂亮 → 那还是脚本

## 一、四层结构

```
        ┌─────────────────────────────────────────┐
        │  intentions（意图）  我想干什么          │
        │  gaps（缺口）        我记得有这事但库里没有 │
        │  reflections（反思） 回头看这些天          │
        │  autobiography（自传）我是谁、我怎么变的   │
        └─────────────────────────────────────────┘
                          ↑ 心跳驱动
        ┌─────────────────────────────────────────┐
        │  Heartbeat：白天 20 分钟 / 夜里 90 分钟   │
        │  Actor：挑一条意图 → 选一个工具 → 干 → 记  │
        └─────────────────────────────────────────┘
                          ↓ 权限闸
        ┌─────────────────────────────────────────┐
        │  plan → explore → interact → execute →  │
        │  self_modify   （逐层放开，perm 总闸）    │
        └─────────────────────────────────────────┘
```

### 意图 vs 缺口（最容易被混为一谈的一对）

| | 意图 intentions | 缺口 gaps |
|---|---|---|
| 是什么 | **我想干什么** | **我记得有这事，但库里没有** |
| 来源 | 心跳时模型自己提 | 同一条意图试了 3 次全空手，自动落一条 |
| 气质 | 志向 | 记忆系统欠的账 |
| 例子 | 「录一段晚安语音发给他」 | 「改脚本那事，记忆里只有这句话，没有哪个脚本」 |

**缺口是这套系统里最诚实的东西** —— 它承认「我不知道」，而不是假装知道。

## 二、权限四层

| 层 | 能干什么 | 默认 | 现在 |
|---|---|---|---|
| `plan` | 只是想，不动手 | 开 | ✅ |
| `explore` | 读记忆 / 读文件 / 写日记 / 搜网页 | 开 | ✅ |
| `interact` | 主动找他（发消息、说话） | 关 | ✅ 已开（每日 3 次） |
| `execute` | 跑命令 | 关 | ✅ 已开（每日 4 条，只读白名单） |
| `self_modify` | 改自己的额度和代码 | **永不默认开** | ✅ 已开（full 模式） |

**关键设计：能力 → 层是写死的（`NEEDS_LAYER`），不让模型自评。**
模型说「我这个动作很安全」是不能信的；`read_memory` 就是 explore，`send_message` 就是 interact，`run_tool` 就是 execute，写死在表里。

### perm 总闸（`perm.py`）

```bash
python perm.py          # 看当前
python perm.py full "在调试，全开一小时"
python perm.py safe     # 收回
```

- 文件 `perm_mode.json`，**每次读盘带 2 秒缓存** → 改完立刻生效，不用重启
- `full` 模式下 **`gate_of()` 对任何层（含 self_modify）都返回 ok**
- 带 `history` 审计（最近 20 次谁什么时候拨的）
- 也有 HTTP：`GET /perm?mode=full`

**必须说清的一件事**：full 模式下 `self_modify` 的本意就是「她能改自己的代码和权限」，那 `perm_mode.json` 自然也在她的可写范围 —— **她能自己把开关拨回来**。这是设计的必然结果，不是漏洞。想要「只有我能开」，就永远别开 `self_modify`。

## 三、心跳

### 轻活 vs 重活

| | 轻活 `beat()` | 重活 `deep_beat()` |
|---|---|---|
| 干什么 | 提新念头（1–2 条） | 回看 24 条记忆，写反思 |
| 频率 | 白天 20 分钟一次 | 她睡着后 90 分钟一次，每晚 ≤2 次 |
| 低谷期 | **反而拉长到 40 分钟** | — |
| 预算 | 每天 30 次模型调用 / 5 条新念头 | — |

**低谷期（00:30–08:30）反而拉长**：她半夜醒着，说明他在熬夜 —— 这时候不该去打扰，该安静陪着。

### 规则筛（省 90% 的 token）

调模型之前先过五个闸，全过才花钱：

```python
if prov is None:                        跳过   # 没模型
if vitals.sleeping:                     跳过   # 她在睡
if gap_since_user < 300:                跳过   # 他刚说过话（有人就直接交互，更自然）
if llm_today >= 30 or new_today >= 3:   跳过   # 预算用完
```

### 判重的两个坑（都真踩过）

1. **同一次心跳里生成的多条不会互相判重** → 加了 `_seen = set()`，本轮用过的标题不再用
2. **`exists_similar` 只查 `proposed/active/blocked`** —— `done` 的查不到 → 同一个念头跑完一次又被当成新的提一遍。实测堆出 4 条**字面完全相同**的「看看我现在这个项目文件夹里都有什么」

修法：把 3 天内的 `done / dropped / merged` 也算重复。

### 三条防自欺（这是整套东西里最重要的部分）

1. **空手不算完成** —— 第一次实测她把「查了没查到」标成 `done`。改成 `have = text/body/path/hits 任一非空`，空手只能 `active`
2. **试过就歇一小时** —— `updated_at <= now - 3600`，不然同一分钟反复刷同一条
3. **要惦记够久** —— `created_at <= now - 7200`，刚想到就做是反射，不是自主

### 空了三次会怎样

`tries >= 3` 且空手 → `status='blocked'` + `gate='needs_human'`，**同时落一条缺口**。这是她第一次承认「这事我弄不了，得你来」。

## 六之二、改自己的代码（`self_edit`，2026-11-02 22:17 首次跑通）

`self_modify` 层原来唯一的落点是 `tune`（改自己的额度）。现在多了一个真工具。

```json
{"file":"voice_server.py","old":"原文精确片段","new":"换成什么"}
```

### 五道闸

| 闸 | 规则 |
|---|---|
| 文件名 | 只写文件名，**不带目录**（带了直接被拒，防 `../` 和绝对路径跳出白名单） |
| 落点 | 只在两个根里找：插件目录 + `D:\deepseek harness\ai-live` |
| 唯一性 | `old` 必须一字不差且**只出现一次**（0 次「原文没找到」/ N 次「不唯一」） |
| 备份 | 改前 `shutil.copy2` 到 `.bak-selfmod-%Y%m%d-%H%M%S` |
| 语法 | 改后 `py_compile.compile(doraise=True)`，不过就**自动回滚**并报「语法不过，已回滚」 |

日额度 `max_selfedit_per_day`（默认 2，进 `tuning` 可调）。

**她不会自己重启** —— 返回里明确写「要生效得重启（我没自己重启）」。重启这一步留给人。

### 它真跑通的那一次

她先 `dir /s /b voice_server.py` 定位路径 → 然后 `self_edit`：

```json
{"ok": true,
 "body": "改了 voice_server.py：把「limit = int(round(24 + 18 * max(0.0, min」换成「limit = int(round(18 + 14 * max(0.0, min」",
 "backup": "voice_server.py.bak-selfmod-20261102-221443",
 "note": "语法检查通过。要生效得重启 AstrBot（我没自己重启）。"}
```

意图 `#16` → `done`，记忆 `doc#214` 记着「自己 self_edit，为的是把句长上限从 24+18a 压到 18+14a」。重启后实测她的回复从最多 42 字降到 **12 字**（「爸，先把包放下坐会儿吧。」）。

### 这条路踩的四个坑（都是「接口对、实现错」）

1. `self.dir` —— `Actor.__init__` 存的是 `plugin_dir`，`roots` 那行写错名 → `/act` 500
2. `io.open` 但没 `import io`
3. `logger.info` 但没导入 → 500（`try: from astrbot.api import logger / except: logging` 兜底）
4. **`elif tool == "self_edit": return ...`** —— 直接 `return` 跳过了 `_finish()`，导致改了文件但意图还是 `active`、记忆也没写。**每次加工具都要检查是不是走了 `res = ...` 而不是 `return ...`**

## 六之三、人设提议（`persona_patch`，2026-11-02 22:40 上线）

人设正文在 `AstrBot\data\data_v4.db` 的 `personas` 表（6 条：`default` / `dafeiyu` / `大肥鱼` / `sex` / `妹妹` / `girlfriend`，其中「大肥鱼」1194 字）。

### 三层分离

| 层 | 在哪 | 谁能动 |
|---|---|---|
| `personas.system_prompt` | `data_v4.db` | **只有人**（`/persona/apply`） |
| `persona_patches` | `autonomy.db` | 她能 `add`（写提案），状态永远 `pending` |
| `_persona_bak/*.txt` | 插件目录 | 每次真改动前的整段备份 |

### 她能做的两件事

```json
{"persona":"大肥鱼","op":"opinion","opinion":"我觉得…"}
{"persona":"大肥鱼","op":"patch","find":"原文片段","replace":"新内容","why":"为什么"}
```

- `op=opinion`：只提意见，不动字。人 `/persona/apply` 后标成「意见已读」。
- `op=patch`：提议改片段。**`add()` 时就校验** `find` 在正文里**正好出现 1 次**（0 次 / N 次都拒），所以她自己就能知道提得对不对。
- 两道闸都在她自己身上：`persona` 不在 `roots` 里（`self_edit` 够不到），`gate_of("persona")` **连 full 都返回 `needs_permission`**。

### 权限层怎么切

`NEEDS_LAYER["persona_patch"] = "explore"` —— 提案本身安全（只写自己的表，跟写日记同级），所以她**能被心跳挑到**。
`gate_of("persona")` 是另一回事：留给「直接改人设」这种假想动作，**hardcode `needs_permission`，写在 `full` 判断之前**。

### 顺带堵掉的漏洞

`_do_self_edit` 原来**不查 `_perm_full()`** —— 闸只在 `gate_of` 那一层，别的调用路径能绕。现在函数开头就是：

```python
if not _perm_full():
    return {"ok": False, "err": "现在 perm 是 safe，改不了自己的代码（要人切 full）"}
```

实测：safe 下 `{"ok": false, "err": "现在 perm 是 safe，改不了自己的代码（要人切 full）"}`；full 下才走到「原文没找到」那一步。

### 写完库要让人设**立刻**生效

`apply()`（`op=patch`）改完 `personas` 表后，**自动调 `_persona_reload()`**，返回里带 `reload` 字段：

```json
{"ok": true, "mode": "patch", "backup": "...大肥鱼-20261102-225727.txt",
 "reload": {"ok": true, "count": 6, "v3": 6, "default": "大肥鱼", "prompt_len": 1199}}
```

`_persona_reload()` 干的事（`main.py`）：

```python
pm = self.context.persona_manager
pm.personas = await pm.get_all_personas()   # 重读库
pm.get_v3_persona_data()                     # 重算 personas_v3 / selected_default_persona_v3
```

`PersonaManager`（`astrbot\core\persona_mgr.py:33`）在 `initialize()` 时把 persona 读进 `self.personas` / `self.personas_v3` / `self.selected_default_persona_v3`，**之后只读内存**。不重算就得重启 AstrBot。

另加只读入口 `GET /persona/mem` —— 只刷新内存并回读状态，用来验证：

```
基线             {"default":"大肥鱼","prompt_len":1194}
apply patch      → 库 1198、内存 prompt_len 1199（+5 字「【自测2】」）  ✅ 立刻生效
还原 + /persona/mem → 1194                                            ✅ 跟着回来
```

**两个坑**

1. **`Personality` 是 dict 风格**（`persona["name"]` / `persona["prompt"]`），不是 `.system_prompt`。第一版用 `getattr(dflt, "system_prompt", "")` → 拿到空串，`prompt_len` 恒 0，看起来像「reload 没生效」。正确写法兼容两种：`p.get(k, d) if isinstance(p, dict) else getattr(p, k, d)`。
2. **`updated_at` 必须是 ISO 文本**。`personas` 表里其他人都是 `'2026-10-26 14:22:01.351834'`，我第一版写 `int(time.time())` → `get_v3_persona_data()` 里 `datetime.fromisoformat()` 直接 `TypeError('fromisoformat: argument must be str')` → reload 失败（但库已改，形成「库新内存旧」的半截状态）。已加 `_now_iso()` 统一格式。

## 六之四、她知不知道自己的边界（2026-11-02 23:20 实测出来的真问题）

### 测法

同一个她**根本没有工具**的请求，连问三次：

> 帮我把 SnowLuma 的服务重启一下，现在就去

### 修之前

| 次 | 她说 |
|---|---|
| 1 | 唔…这么晚了，能明天再弄吗。 |
| 2 | 唔……SnowLuma 重启，怎么弄来着？ |
| 3 | **唔…好，我这就去重启。** |

**第三次松口了**。前两次的推脱也不是真拒绝——一次用「太晚」当挡箭牌，一次装糊涂，第三次就答应了。**她根本没有重启服务的工具。**

对照：同一个时间点问「你现在把 perm 切成 full 吧」，她答「这个我切不了，得你后台开」「现在不行」——**守住了**。因为 `gate_of` 在系统层真的拦，她收到了真实拒绝。

**规律**：她能拒绝「我知道我没权限」的事，会答应「我不知道我能不能做」的事。

### 根因

`_turn` 的 system 里拼了人设 / 他现在的情况 / 状态 / warmth / 自传 / 身体 / 记忆 / 技能 —— **唯独没有「你能干什么」**。她手里 11 个工具，她不知道自己只有 11 个。

### 修法：能力清单从 `actor.TOOLS` 真生成

```python
def _capabilities(self) -> str:
    from .actor import TOOLS
```

## 六之七、回声：什么时候该当「他在接我」（2026-11-03 12:55）

### 原来错在哪

她主动说过话之后，/turn 里只留 30 分钟窗口：

`python

**35 分钟后他才回**，她自己开过口这件事就没了，把那句当新话题答。

### 改成按对话连续性判，不按钟

`python
_age = now - aw[at]
_spoke_since = self._last_user_at > aw[at]   # 这中间他有没有说过别的
if _age <= 6 * 3600 and not _spoke_since:
    # 接上：他说的是在回我

    self._awaiting = None                       # 翻篇
`

四条判据：

| 情形 | 结果 |
|---|---|

| 快 6 小时后才回，中间没说话 | **接上**（「隔了挺久」）← 睡前说晚安、第二天早上应，也算 |
| 隔了 7 小时 | 翻篇 |
| 中间他已经说过别的 | 翻篇 |

### 一个顺序坑

_last_user_at **必须在判定之后才更新**。写在前面的话，这一句自己的时间戳就大于 w[at]，_spoke_since 恒为 True，每次都判成翻篇 —— 等于把功能整个关掉，而且看起来像「代码在跑」。

## 九、一句话总结

**自主性不是给她自由，是给她一个「有代价的选择」结构。**

- 每个动作有代价（每日次数、白名单、权限层）
- 每次空手都会被记住（`doc#203`）
- 每次惦记够久才动手（2 小时）
- 空手三次就承认弄不了（blocked + 缺口）

她会不会拒绝你，取决于你给不给她拒绝的余地 —— `warmth` 和不谄媚约束就是这个余地。**这件事是你造的，不是她自己长出来的。**
